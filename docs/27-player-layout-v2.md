# 27 · 播放页版式 v2：列表居中，播放键压底，输入源常显

三条用户意见，逐条对应改动。

## 1. 播放列表放到封面下方，居于整个界面中部

之前列表被压在最底部（`weight(0.85f)` 跟在音量、输入源之后），结果是：
控制键在中间、列表在最下，滚动列表时手指要够到屏幕底边。

现在从上到下是：

```
顶栏（设备名 · 输入源 · 播放状态）      ⋯
封面（weight 1.05f，取 min(宽,高) 保持正方形）
曲名 / 歌手
[播放列表 N][投流与日志]   设备 N 首 · 第 k 首
┌── 中部列表：全屏唯一的滚动区（weight 1f）──┐
└───────────────────────────────────────────┘
进度条 + 时间
音量
输入源（当前源钉在第一位）
循环 ⏮ ▶ ⏭ ■        ← 压在最下方
```

两块都用 `weight`（1.05 : 1）而不是写死高度 —— 矮屏（640dp）和高屏（900dp）
都能同时留出封面和列表的位置；写死高度必然在某一端出问题。

**仍然是单层**：没有 Dialog、没有 BottomSheet、没有第二个滚动轴。
`LazyColumn` 只在中间那一块里，所以「列表滚动抢走播放键手势」不会再出现。

## 2. 播放整行压到最下方

主控行（循环 / 上一首 / 播放暂停 68dp / 下一首 / 停止）从中间移到 Column 的最后一项。
它在布局里是**固定高度、不参与 weight 分配**的，所以任何屏幕尺寸下都在屏内、永远可点。

顺序调整：进度 → 音量 → 输入源 → 主控。这样"眼睛最后落点是播放键"。

## 3. 输入源必须显示当前值

改了两处：

- **顶栏副标题加前缀**：原来只写「网络播放 · 本地播放列表」，看不出这是输入源；
  现在是「**输入源** 网络播放 · 本地播放列表 · 播放中」。
- **切换行里当前源钉在第一位**：原来 `PlayerSource.all` 固定顺序（wifi/line-in/bluetooth/udisk/optical）
  横向滚动，如果当前是「光纤」（最后一个），窄屏上它会被滚出屏幕外，用户完全看不到当前源。
  现在把当前源提到第一个位置，并在前面加一个 `●` 圆点 + 加粗 —— 不靠颜色深浅去猜。

当前源判定仍然以**设备回报的 `mode`** 为准（`PlayerSource.currentIdOf`），
不是记住"上次点了哪个" —— 机身按键也能切源，界面要跟着变。
