# 79 · 脚本仓库模块（core-script）：一个中间件，装"用户交给我们的脚本"

> 写于 2026-11-04 · 依据 main `5f7babb` + 并发刷新
> 用户：「第四项能否成为一个中间件模块考虑一下」→「我还是坚持做一个中间件模块，这个在未来会有大用处，做吧」

---

## 零、三行摘要

1. **`docs/74` 第 4 项（导入脚本）抽成了独立模块 `core-script`** —— 纯 JVM、零依赖、可 publish。
2. 它不是"洛雪的脚本管理器"，是**任何可插拔内容源的脚本仓库**：校验、存盘、列出、删除、当前启用哪一支。
3. **"洛雪脚本长什么样"不在这个模块里** —— 由 `core-lx` 提供 `LxScriptValidator`。加一种新格式 = 加一个实现，仓库一行不改。

---

## 一、为什么单独成模块（而不是 app 里的一段界面代码）

| 如果放进 app | 后果 |
|---|---|
| 界面里校验 + 存盘 | 换一个界面（比如从云端曲库导入）就要再写一遍校验 |
| 每个入口自己拼路径 | 目录规则散开，改一次要全仓搜 |
| 「有没有脚本」各处自己判断 | 播放页 / 在线曲库页 / 诊断各存一份状态 —— 就是 docs/41 那 7 条病 |

抽成模块后，**"装了什么脚本"只有一处真相**，谁要用都问它。

用户的原话是"未来会有大用处"，所以这一版按**可发布**来做（`maven-publish` + 零依赖），
别的宿主（桌面工具、别的 App）`implementation` 一下就能用，只要提供一个 `ScriptStorage`。

---

## 二、三层，各自管一件事

| 层 | 类型 | 会不会变 |
|---|---|---|
| **来源** | `ScriptCandidate`（文本 + 来源标记） | **会变**：粘贴 / 选文件 / 将来网址、二维码、剪贴板 |
| **仓库** | `ScriptRepository` | 基本不变 |
| **格式** | `ScriptValidator` 实现 | 会变：一种格式一个实现（现在只有 `LxScriptValidator`） |

将来加"从网址导入"，只需要构造同一个 `ScriptCandidate` —— 校验、存盘、诊断零改动。

---

## 三、磁盘上只有两种东西

```
filesDir/scripts/
  六音音源.js        ← 脚本原文，文件名由 @name 安全化得到
  _active           ← 内容是当前启用那支的文件名
```

**没有索引文件。** 名字/版本/作者/大小/时间全部列的时候现读现解析。

理由：索引会带来"两个真相"—— 用户用文件管理器把脚本拷进来、删掉、改了，
索引还停在旧状态，于是界面显示的和实际有的不一致，而这种不一致**只在下次重启后才暴露**。
现在"手动扔进目录的脚本"会立刻出现在列表里（有单测锁这一条）。

代价：每次列脚本要读几份几十 KB 的文本并解析一遍。家里几支脚本，可以忽略。

---

## 四、四条行为规则（都有单测）

1. **四种失败分开说**：空文本 / 没有头部注释块 / 有头部但缺 `@name` / 其它。
   合并成"导入失败"，用户只会反复试同一份。
2. **同名导入 = 更新**，并回报上一版版本号（`v1.0.0 → v1.2.1`）。
3. **改了名算新的一支，并存**，不删旧文件 —— 脚本名字是脚本自己声明的，
   我们判断不了"这两支其实是一支"；乱删用户文件的代价远大于列表里多一条。
4. **第一次导入自动启用**。导完还要再点一次"启用"才能用，等于"导了没用"；
   但已有启用项时不抢用户的选择。

---

## 五、一个必须挡住的坑：名字里的路径

`@name` 是脚本自己写的。写成 `../../etc/passwd` 时，如果直接拿它当文件名，
就会写到脚本目录外面去 —— 这不是假想的攻击，任何能改脚本头的人都能触发。

所以 `fileNameOf()` 逐字符过滤：路径分隔符、Windows 不允许的字符、空白、控制字符换下划线；
中文保留（文件系统支持，用户也认得）。有单测断言"名字像路径也跑不出目录"。

> 这里刻意不用正则：正则要穿透「Kotlin 字符串 → 正则字符串 → 字符类」三层转义，
> 本会话第一次就写错了一个反斜杠，把 `\s`（空白）写成了字面 `\s`（反斜杠+s）——
> 结果是空白不被过滤，而这种错单测不一定暴露。显式字符集一眼就懂。

## 六、这一批**没有**做的（说清楚）

| 没做 | 为什么 | 什么时候做 |
|---|---|---|
| 导入界面（粘贴/选文件） | 先把仓库验证透，界面做出来才有意义 | 下一批 |
| 诊断段「脚本状态」 | 铁律一：跟功能同一批。功能（界面）还没接，现在挂一段只会显示 0 | 下一批，与界面一起 |
| 「哪支脚本失效了」 | 需要执行层回报 `musicUrl` 失败 | 接上搜索与取流之后 |
| 脚本签名/来源校验 | 自用工具，脚本本来就是用户自己找的 | 不做 |

## 七、测试

`core-script` **15 个用例**，全部跑在临时目录上（不碰真机、不碰 Android）：

| 组 | 锁什么 |
|---|---|
| 校验 | 四种失败分开；空名字不算合法 |
| 导入 | 首次自动启用；同名更新带上一版版本号；不同名并存不删文件 |
| 安全 | 名字像路径跑不出目录；`_active` 不出现在列表里 |
| 磁盘 | 手放的脚本立刻可见；不是脚本的文件进 `unrecognized()` 而不是被静默藏掉 |
| 存储 | 读不存在的文件返回 null；覆盖后没有 `.tmp` 残留 |

`core-lx` 新增 `LxScriptValidatorTest` 5 个用例：真实脚本、空白、别家脚本（无头部）、
缺名字（不是"无头部"）、`@name` 值为空。
