# 31 · 播放页去掉输入源行；首页按原厂卡片重做

两条要求，分开说。

## 一、播放页：底部「输入源」整行移除

原来播放页最底部有一排可点的输入源胶囊（网络播放/线路输入/蓝牙/U 盘/光纤），
现在整行删掉，连 `InputSourceRow` 这个 composable 一起删除（不留死代码）。

**没有丢失能力**：

- 当前输入源仍然在**顶栏副标题**显示（「输入源 DLNA 渲染器 · 播放中」），
  它来自设备回报的 `mode`，机身按键切了源界面也会跟上；
- 切换输入源仍然在**设备设置页**里（`DeviceSettingsScreen` → 输入源），
  那里原来就有，而且是"点开设置再切"的语境，比在播放页误触更合理
  —— 真机实测切走 Wi-Fi 的源会让手机控制不到设备，这个动作不该放在最容易误触的位置。

## 二、首页：保留我们的特色 + 加原厂卡片

### 加了原厂的什么

| 原厂 | 我们的实现 |
|---|---|
| 顶栏「设备列表」+ 添加 + 刷新 | 保留「我的音箱」标题，右上角补 `+` 与 `↻`（原来刷新藏在「添加音箱」折叠区里，要展开才看得到） |
| 卡片右上角齿轮 | 齿轮直接进这台设备的设置页（`vm.open(device)` + `SubPage.Settings`） |
| 卡片内「正在播放」条（封面 + 曲名） | 缩略图 + 曲名 + 「N 首 · 第 k 首」（`plicount/plicurr` 来自 3 秒轮询） |
| 卡片内音量条 + 声道标签 R/LR | 音量条拖动**立刻**下发（本地乐观值 + 合并通道）；声道标签由 `getPlayerStatus.ch` 决定：`0→LR`、`1→L`、`2→R` |
| 虚线分隔 + 「如何在多音箱同步和独立播放间切换？」+ 「全部播放」大按钮 | 同样加上；「全部播放」走 `vm.playAll()` |

### 保留了我们的什么（没有为了像原厂而砍掉）

- **在线/离线/组内三态**：原厂不显示 IP 与在线状态；我们的卡片第二行显示
  `192.168.99.164 · 在线`，入组从机显示 `同步播放中 · 属 doss1`（它连不上路由器侧，
  说"离线"是撒谎，这条之前专门修过）；
- **多房间卡片**（首页最底部）：原厂靠拖拽两台设备成组，我们是一键组网 + 每台独立音量/声道；
- **迷你播放条**：底部导航之上常驻，点开进播放页；
- **添加音箱折叠区 + AP 直连配网 + 手动填 IP**：原厂只有搜索；
- **状态色与对比度门禁**：卡片底是派生深色渐变，文字用 `OnDarkPalette` 恒定白系，
  `ThemeContrastTest` 在 CI 里卡 4.5:1。

### 「全部播放」的一个真实修正

原实现是 `setPlayerCmd:resume`。实测（`.164`，`plicount=3`、`status=pause`）：

```
setPlayerCmd:resume        → OK，但 getPlayerStatus 仍 status=stop（命令回 OK ≠ 生效）
AVTransport.Play           → 200，随后 status=play、curpos 递增
```

所以改成 **`AVTransport.Play` 优先，失败才退 httpapi `setPlayerCmd:play`** —— 与原厂一致，
也符合本项目的既有纪律：控制面以 UPnP 为主，httpapi 只做兜底。

## 三、验证

- `:app:compileDebugKotlin` / `assembleDebug` 通过
- 全量 **412 用例 0 失败**
- 真机：`.164` 有队列时 `AVTransport.Play` → 200，`status=play`、`curpos` 递增（本轮实测）
- 读不到封面的处理是**如实说明**：设备不回填元数据（`Title` 是 HEX、无 `albumArtURI`），
  所以缩略图用曲名首字 + 派生色块，不假装有封面。
