### 1.3 三个已经能确认的结构病

**病一 · 中转页**（点进去只是再选一次）

- `SourcesScreen`（46 行）＝ 7 个入口的列表
- `MyMusicScreen`（232 行）＝ 6 个入口的列表

用户抱怨过同类问题（洛雪从"媒体库→其它入口→洛雪"五次操作提到一级），
但**同类问题在别的源上仍然存在**。

**病二 · 职责重叠的四个页面**

```
LibraryScreen (599)  ┐
MyMusicScreen (232)  ├─ 都在回答"我有什么音乐"
QueueScreen   (345)  ┤
SourcesScreen (46)   ┘
```

**病三 · 分类维度混着用**

```
设备  ← 对象
播放  ← 动作
洛雪  ← 一个内容源（品牌）
媒体库 ← 一堆东西的集合
```

四个格子用了三种维度。**这是"不对了"的根因** —— 不是排列不好看，是没有统一维度。

## 二、三条已确认的待办

### U1 · 底部导航重排

**现状**：4 格 / 三种维度混用 / 13 个二级页。
**判据（重做时必须满足）**：

1. 一级入口按**对象**分（设备 / 内容 / 遥控 / 我），不按"播放 vs 遥控"分
2. 同类能力不拆两格（洛雪和电台都是内容源，要么都在一级、要么都在内容里）
3. **每格点进去第一屏就能办事**，不许再有"进去再选一次"的中转页（杀掉 `SourcesScreen` / `MyMusicScreen` 这种）
4. 底部最多 5 格；再多换导航形态，不硬塞

### U2 · 首页设备按类型隔离

**现状**：`HomeScreen` 里 DOSS 与通用 UPnP 渲染器**混排**，界面上几乎不区分。

全仓 `*Screen.kt` 里 `DeviceProfile.` 只有 **1 处**（`HomeScreen:303`，还是 `?: UNKNOWN` 兜底）。
用户看到的是"四台一样的设备"，而电视盒子那台没有设备侧队列、不能组网、没有电量/固件。

**判据**：

1. `DeviceCapabilities` 补两个根位：`canPlayAudio` / `canBeRemoted`
2. 按**能力**分组，不按品牌：
   - 我的音箱（有设备队列 + 能组网）
   - 其它播放设备（能放声音但无队列/无组网）
   - 发现未添加
3. 每组显示**它能干什么**，不列它做不到什么
4. `check-profile-in-ui.py` 转 error

### U3 · 遥控类（红外 / 蓝牙 / WiFi）

**现状**：

| 能力 | 代码 | UI |
|---|---|---|
| 红外 | `NecEncoder` + `IrBlaster` + `IrStatus` | 只在设备设置页一张卡（试发一个键） |
| 蓝牙 | 无 | 无 |
| WiFi 遥控 | 无 | 无 |

**判据**：功能不存在的入口不画（`docs/86` 原则）。每个能力做到**真机可用**才加入口：

| 前置 | 判据 |
|---|---|
| 红外 | ① 确认手机有发射器 ② 接码库（Flipper-IRDB CC0，30 万条） ③ 能发出一个真能控电视的键 |
| 蓝牙 | 至少能扫到并连上一台 BLE 遥控/耳机 |
| WiFi | 确认目标设备协议，且有一条真机可用命令 |

## 四、重设计从哪一步开始（等时机到了照这个做）

**第一步不是画界面，是列清单。** 三个问题逐项过：

1. **这个页回答什么问题？** （不是"展示什么"，是"用户带着什么疑问进来的"）
2. **这个答案还有别的地方给吗？** 有就合并
3. **删掉它，用户会迷路吗？** 不会就删

按这三问过一遍现在的 17 页，先得到"合并/删除"清单，再谈布局。

**已知可以直接判的几处（等时机到了再复核）**：

| 页面 | 倾向 | 理由 |
|---|---|---|
| `SourcesScreen` (46) | **删** | 纯入口列表，嵌进一级页 |
| `MyMusicScreen` (232) | **删/并** | 同上，且与 LibraryScreen 重叠 |
| `QueueScreen` (345) | 并入播放页 | 播放页已有队列面板 |
| `DeviceContentScreen` (183) | 并入 QueueScreen 或播放页 | 与 Queue 重叠 |
| `ProvisioningScreen` (342) + `WpsGuideScreen` (161) | 合并 | 同属配网，两次一次性流程 |
| `LxSearchScreen` (147) | 归入"内容搜索" | 它只是一个源，不该占底部格子 |
| `DiagnosticsScreen` (135) | **提到可见位置** | 最常用排障入口，现在埋最深 |

**注意：以上是"候选"，不是决定。** 真正动手前要重新核一遍（因为底层架构还会动）。
