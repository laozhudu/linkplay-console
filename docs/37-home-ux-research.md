# 37 · 主页为什么"差了点东西"：对照成熟产品的三条修正

用户反馈三件事：
1. 主页功能用着不舒服，"总觉得差了什么"（说不清）
2. 拖拽组网和解除组网不好用
3. 图标点了不改变 —— 比如「全部播放」按下去应该变成「全部暂停」

我去查了成熟产品怎么做的，下面每条都有出处，然后对照我们现状。

## 一、研究结论（三条）

### 1. 播放/暂停按钮显示的是"将发生的动作"，不是当前状态

UX StackExchange 上这个问题（*Should a toggle button show its current state or the state to which it will change?*）
有 572 赞，最高票结论：

> 播放/暂停按钮显示**动作**（点了会发生什么）；其他状态开关（随机、循环）显示**当前状态**。
> 所有主流播放器都是这样，反着做会被用户当 bug 报。

我们的问题正好撞在这条上：`全部播放` 按钮文字写死，永远调 `playAll()`。
设备已经在放，按钮还是"全部播放"—— 点了没变化，用户当然觉得"图标点了没反应"。

### 2. 分组的主流交互是"勾选 + 应用"，不是拖拽

Sonos 官方文档（*Group and ungroup rooms*）：

> 在 Grouping 菜单里 **勾选/取消勾选**房间来加入或移出组，然后选 **Apply**。
> 3 台以上还可以选 **Everywhere** 一键全组。

也就是说：**连 Sonos 都不用拖拽做分组**。拖拽给不了三件事 ——
一次选多台、看见"现在在哪些组里"、应用前取消。这正是用户说"拖拽没那么好用"的根因。

（Sonos 另有"长按机身上的播放键"把设备加入正在播放的组，那是硬件操作，不是 App 手势。）

### 3. 主页需要一个常驻的"现在播放"条

Music Assistant 的 Player Bar 是常驻的全局控制条（曲名 + 播放控制 + 音质标签 + 溢出菜单），
Sonos 的 Now Playing bar 也是常驻在底部。
我们之前主页只有一堆设备卡片，**"现在在放什么、一键停"要点进播放页才有** —— 这就是"差了点东西"。

## 二、对照现状（三处不符）

| 研究结论 | 我们之前 | 现在 |
|---|---|---|
| 播放键显示动作 | 「全部播放」写死，永远 playAll | 双态：在放 → 「⏸ 全部暂停」（主色实心），不在放 → 「▶ 全部播放」 |
| 勾选 + 应用分组 | 只能长按拖拽；没有面板、看不到当前组、不能取消 | 新增 ⧉ 面板：勾选设备 + 「全部同步（Everywhere）」+ 应用，逐台进度 |
| 主页常驻播放条 | 无（只有设备卡片） | 新增聚合条：曲名 + 「N 台同步」+ 播放/暂停 + 组网入口 |

## 三、这轮具体改了什么

### core-protocol（纯逻辑，11 条单测）

`multiroom/GroupPlan.kt` —— 勾选式分组的**差异计算**：

```
diff(current, selected, masterUuid) → Plan(join, leave)
```

三条约束都锁在单测里：
- **主机永不参与** join/leave（界面上主机那行也是勾选态，不能因此"把主机加进去"）；
- uuid 比较**大小写/空白归一**（设备回报常带 `uuid:` 前缀）；
- 空白项直接丢弃（否则会算出一台幽灵设备）。
- `Everywhere` 只在 ≥3 台时提供（Sonos 同款规则，两台时"全选"没有额外价值）。

### ViewModel

- `ConsoleUiState.anyPlaying` / `playingTitle` / `groupSize`：**聚合播放态的唯一来源**。
  主页聚合条、底部大按钮、迷你播放条三处都读它 —— 各自算一次必然出现
  "条上说暂停、按钮说播放"。
- `togglePlayAll()`：按 `anyPlaying` 决定 play 还是 pause。
- `toggleDevicePlay(device)`：卡片上的小按钮。**组内从机直接拒绝**并给一句话
  （它跟随主机，单独下发是无效命令）。
- `applyGrouping()`：先移出（`SlaveKickout`）、再加入（`ConnectMasterAp`），
  **串行**执行 —— 并发下发时第二台可能正在重连，命令会直接失败。
  全部下发完等 6 秒统一刷新（真机实测 8 秒左右建成），期间面板显示"加入 X…/等待建链…"。

### 界面

- 主页顶部**聚合播放条**（Sonos Now Playing / Music Assistant Player Bar 的等价）：
  曲名 + 主机名 + 「N 台同步」+ 播放暂停 + ⧉ 组网入口。
- 底部大按钮改双态（在放时主色实心，一眼看出点下去会停）。
- 卡片内加 ▶/⏸ 小按钮（组内从机不显示）。
- **解除组网加二次确认**：从机会离开当前 Wi-Fi（真机约 3 秒回来），
  误触代价是"音箱不见了"。原来是一点就走、静默 3.5 秒。
- 拖拽保留，但提示文案改成「点 ⧉ 勾选要同步的音箱；也可以长按卡片拖到另一台上」。

## 四、验证

| 项 | 结果 |
|---|---|
| `GroupPlanTest` | 11 条全绿（主机排除、大小写归一、空白丢弃、Everywhere 阈值、顺序稳定） |
| 全量单测 | **574 用例 0 失败**（上轮 563 + 11） |
| 真机 | `.164` `AVTransport.Play` → `status=play`；`Pause` → `status=pause`（双态的数据来源可靠） |
| 未验证 | 手机上实际点击手感、勾选面板在 3 台设备时的布局 |

## 五、还没做的（下一轮候选）

- 组内**逐台音量**放进分组面板（Sonos 的做法：Apply 前就能调每台音量）
- 卡片上显示"跟随 doss1"而不是只显示组内标签
- 主页排序：正在播放的设备置顶（Sonos 的 Rooms 列表就是按活跃度排）
