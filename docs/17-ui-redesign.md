# 17 · 界面第二轮整改（按用户四条意见）

用户原话：

> 1，多房间同步增和减音箱做的不好看，每个音箱的音量和声道是可以进行单独设置的，多房间建议放在首页进行可视化配置
> 2，播放界面播放列表功能没法用，建议播放器界面完整复刻qq播放器样式。音量同步不跟手，原版app是很好的跟手
> 3，多个几个页面ui设计不统一，建议必须与首页逻辑统一
> 4，设置页面与已有的一些页面功能重叠，应该裁剪掉。

逐条对应改造如下。

## 1. 多房间搬到首页，做成可视化配置

**位置**：`room/MultiroomCard.kt`（新文件）+ `ConsoleViewModel` 新增 `groupMasterIp` / `groupMembers`。

- 首页第一屏就有「多房间」卡片，只在「已保存 ≥ 2 台」或「已有组」时出现。
- 结构画成树：**主机块在上（高亮底色）→ 从机块整体右缩进**。不画连线也不画拓扑图 ——
  缩进 + 底色已经足够表达"谁挂在谁下面"，再多的线条只会挤。
- 每台设备一个独立的控制块：
  - **音量**：自己的 `Slider`，拖动即下发。
  - **声道**（仅从机）：`立体声 / 仅左 / 仅右` 三个小 chip。
  - 从机块右上角「✕」= 移出组。
- 「＋ 加音箱」按钮弹列表选一台加入；按钮在组已存在时显示「＋ 加音箱」，否则「＋ 组起来」。

**协议事实**（真机验证）：

| 操作 | 命令 | 实测 |
|---|---|---|
| 主机音量 | `setPlayerCmd:vol:<0-100>` | 42 → 60 回读一致 |
| 从机音量 | `multiroom:SlaveVolume:<从机IP>:<0-100>` | 60 → 30 → 60 回读一致 |
| 从机声道 | `multiroom:SlaveChannel:<从机IP>:<0-2>` | 0 → 1 回读一致 |
| 移出组 | `multiroom:SlaveKickout:<从机IP>` | 参数格式未验证（原厂里是不透明串） |

主机没有声道命令，所以主机块不显示声道 —— 不留假开关。

**为什么不能只写「已连接」**：从机在主机热点网段（`10.10.10.x`），从路由器侧不可达。
所以所有从机操作都必须带**主机自报的从机 IP**，由主机代转。

## 2. 播放页按 QQ 音乐重排，修好列表与音量

**版式**（`playback/PlayerScreen.kt` 重写）：

```
设备名 · 状态                          ⋯ 设置
        大圆角封面（播放时 1.0，暂停 0.94）
             曲名（大、粗）
                  歌手
    1:23 ────────●──────── 4:56
   循环   ⏮   ▶(76dp)   ⏭   ☰ 列表
   🔊 ──────────●───── 60
        （折叠）投流地址与设备日志
```

**播放列表为什么"没法用"——两个原因都修了**：

1. 入口藏得太深：原来把列表直接铺在页面下方，歌一多就把控制键顶到屏幕外。
   现在改成控制行最右侧的列表按钮，点开是 `ModalBottomSheet`（75% 高），
   QQ 音乐就是这个形态。
2. 真 bug：`QueueBus.removeAt` 在**服务没在跑时**（`controller == null`）直接调空对象，
   点了叉毫无反应。现在有本地兜底 `dropLocal`，索引跟着前移。
   点某首同理：服务在跑就 `skipTo`，不在跑就退化成直接投这一首。

单测锁住：`QueueBusTest` 6 个用例（服务缺席可删、删当前曲索引不越界、删空归 -1、
有 controller 时委派、skipTo 委派、越界不抛）。

**音量跟手的根因**：原来每次拖动都走 `setVolume()` → `act()` → 里面有 `busy` 闸门，
第一个请求还没回来，后面几十个全被丢掉，松手才生效。
现在 `setVolumeLive()`：本地值乐观立刻改（数字跟手），值丢进**合并通道**，
后台每 80ms 取最新值下发一次。同理组音量在 `ConsoleViewModel` 里也走合并通道（90ms）。

进度条保持"拖动只改草稿、松手才 seek" —— 逐像素 seek 会让设备进度反复回弹。
