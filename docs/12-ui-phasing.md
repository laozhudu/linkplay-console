# 界面改造的节奏：结构先行，视觉最后

## 结论

**现在不装修。** 只做三件「结构级」的事，视觉打磨（配色细节、字体、动效、插画）留到功能齐了之后一次性做。

原因不是「好看不重要」，而是**返工成本不对称**：

| 类型 | 例子 | 改起来的代价 |
|---|---|---|
| 视觉 | 主色、圆角、字号、间距、深色模式 | 改一个文件、几行常量，**成本≈0** |
| 结构 | 导航层级、页面职责、状态如何呈现 | 新功能一来就可能推翻，**要重画 + 重测** |

所以先做结构，视觉随时可以补；反过来先做视觉，等于给会变的骨架刷漆。

## 这一轮已经做了的结构级改动

1. **主题与令牌**（`ui/theme/Theme.kt`）
   - 深/浅色色板（之前写死 `darkColorScheme()`，浅色模式下颜色全错）
   - `Spacing` 刻度（4/8/12/16/24dp），避免各页面各写一个 dp
   - `StatusColors` 语义色：`ok` / `warn` / `error`
     —— 因为 `CONTROL_LOST`（设备在线、UPnP 掉了）和 `OFFLINE`（整台不通）是两种处置，
     用同一个 `errorContainer` 会让人误以为要查网络
2. **记忆与断点续播**（`session/SessionStore.kt` + `protocol/session/*`）
   - 按**设备 UUID** 记住上次的 NAS 与浏览路径（DHCP 换 IP 也不丢）
   - 队列快照：从第几首继续
   - 这是「结构性」的：它决定了以后打开 NAS 页是「空白搜索页」还是「上次的位置」
3. **错误呈现分层**：连接失败 / 目录打不开 / 控制面掉线 / 设备离线，四类分开写文案

## 明确留到最后的视觉项

- 自定义字体与字号阶梯
- 页面切换动效、列表项动画、播放进度条动效
- 专辑封面占位图、空状态插画、图标体系
- 深色模式的手工微调（现在只是色板，没有逐组件校色）
- 桌面/平板宽屏布局

## 什么时候开始做视觉

当下面这些「功能会改结构」的项都落地之后：

- [x] 记忆（上次的 NAS / 路径）
- [x] 断点续播
- [ ] 编排进前台服务（后台不被挂起）
- [ ] 搜索（ContentDirectory `Search`）
- [ ] 封面显示（`upnp:albumArtURI` 已经在解析）
- [ ] 睡眠定时

其中前三项会改页面结构，后三项只是加控件。前三项做完，就可以开始视觉。

## 一条实践约定

新页面**只用** `Spacing.*` 和 `MaterialTheme.colorScheme.*`，不写裸 dp、不写 `Color(0xFF…)`。
语义状态（正常/需动手/不可达）用 `StatusColors`。这样到最后做视觉时，
改 `Theme.kt` 一处就能全局生效，不用挨个页面搜硬编码。
